Remote baseline attribution still needs CI confirmation.
- A third CodeRabbit pass (on `0ab6724`) found three more gate bypasses in `verify-lockfile.mjs`: a non-object advisory `packages` value silently disabling all policies, policy lookup trusting a single attacker-controllable name (now location + `name` + registry URL), and prefix-only integrity checks accepting `sha512-not-a-digest`. A fourth pass (on `8fea2ab`) found advisory-listed packages with a missing or non-semver `version` passing because `semver.satisfies` returns false rather than throwing; I also closed a missing-`lockfileVersion` fail-open (`undefined < 3` is false). All fixed with tests that fail on the previous script. Lesson: every security gate should treat "cannot evaluate" as a failure, never as a pass.
- Failure mode to avoid: guards that inspect `argv` instead of the resolved command; validate policy data files at load, not only when matched.

## Batch 02 review remediation (PR #98)

- First CI on `6b06b06` failed on Windows (both jobs): my test helper used `os.devNull` for `GIT_CONFIG_GLOBAL`, which Git for Windows cannot open (`//./nul`); fixed with real empty config files. One macOS Node 22 failure was `tests/core/watch.test.ts` ("reports callback failures", 3 s timeout) — an untouched file that passed on macOS Node 24 for the same commit; treated as a pre-existing timing flake pending recurrence.
- CodeRabbit raised six valid findings, all fixed in one corrective push: `#!/usr/bin/env sh` hooks were wrongly rejected (basename taken after the `env` filter); `readBlobs` also read assets the secret scan never opens, which could exhaust the byte/file budget and downgrade later eligible files to warnings; `git-audit` reported every Git failure as "not a work tree" and an `ls-files` rejection escaped (now one contract with a reason; the duplicate `spawnWithInput` helper without timeout/overflow handling was removed in favour of `runGit({ input })`); the MCP handler surfaced messages for every `GIT_*` code (now only the two revision codes); minimum Git corrected to 2.30.
- Lesson: `prettier --write <directory>` rewrites unrelated files; format only the files you touched (this happened three times and was reverted each time).
- Third pass: a Windows-only `EBUSY` showed the staged-blob reader rejected before the killed `git cat-file` process exited (the child kept the repo directory locked); it now rejects only after the child exits. CodeRabbit's last review added: validate the Husky v9 dispatcher before redirecting into `.husky/pre-commit` (otherwise the hook would silently never run) and make the subdirectory path-commit test actually commit. The CodeRabbit-only "docstring coverage" advisory check was not acted on (not part of this repository's CI or ruleset).
